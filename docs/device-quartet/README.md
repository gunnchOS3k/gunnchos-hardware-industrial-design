# Device Quartet Research Framework

## Balanced Device Rule

Every research plan version must include this mapping:

```
Student 14.5"       → full-session learning/work benchmark
Handheld Hybrid     → mobile/docked interaction benchmark
DS-XL Coder         → local creation/deployment benchmark
Edge IO Wearables   → low-latency sensing/haptic benchmark
```

No device may be omitted. No device may dominate. Each device represents a distinct workload class and connectivity stress case for evaluating 6G service continuity.

## Framing

The Device Quartet represents four affordable edge-device interaction modes: desk compute, mobile compute, creation compute, and embodied compute.

These devices are research form factors, not finished commercial products. They are defined as four research benchmarks used to evaluate service continuity, latency, reliability, energy use, mobility, and quality of experience across 6G, NTN, local-edge, and degraded/offline environments.

## Device role mapping

| Device | Interaction mode | Research benchmark | Connectivity stress case |
|--------|-----------------|-------------------|------------------------|
| Student 14.5" | Desk compute | Full-session learning/work | Sustained session over degraded broadband |
| Handheld Hybrid | Mobile compute | Mobile/docked interaction | Mobility and handover |
| DS-XL Coder | Creation compute | Local creation/deployment | Local-edge and peer-to-peer |
| Edge IO Wearables | Embodied compute | Low-latency sensing/haptic | Ultra-low-latency body-area |

## Non-negotiables

- No single device dominates the research plan
- Student 14.5" must not disappear behind gaming language
- Handheld Hybrid must not be treated as only entertainment
- DS-XL Coder must be the strongest "learn to build" device
- Edge IO Wearables must not be treated as optional accessories
- Games are latency-sensitive interactive workloads
- Wearables are low-latency sensing/haptic workloads
- Hardware incompleteness is disclosed honestly
- Final manufacturing is not promised as a PhD deliverable
- Each device has a simulation or prototype substitute
